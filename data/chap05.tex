\chapter{总结与展望}

本章对全文工作进行总结，概括主要创新点，并从集群规模、模型类型、异构硬件与框架集成四个方面归纳研究局限，并展望未来工作。

\section{全文工作总结}

本文围绕“面向异构 GPU 集群的多模态大语言模型并行训练技术”这一主题，针对实际环境中普遍存在的设备异构与 MLLM 的模块异构、分阶段冻结训练等特性，从\emph{模型划分与流水线调度}以及\emph{重计算优化}两个层面开展了研究，提出了 MMoH 与 HR-MMoH 两套方法，并在异构集群上进行了实验验证。下文概括主要创新点。

\subsection{主要创新点}

本文的主要创新点可归纳为以下两方面。

\textbf{（1）MMoH：面向异构 GPU 集群的多模态大语言模型高效混合并行技术。}

针对异构集群上 MLLM 训练时存在的负载不均衡、资源利用率低以及冻结场景下冗余计算与通信等问题，本文提出了 MMoH 框架。
其创新点包括：\emph{需求驱动的设备拓扑识别}，根据 MLLM 各模块的计算与显存需求趋势与异构设备的算力—显存供给进行匹配，筛选候选设备拓扑，使需求与供给在趋势上一致；
\emph{复合粒度模型抽象}，针对编码器、投影层与 LLM 基座的结构差异，采用多级粒度将模型重组为模型块列表（编码器按子模块合并、LLM 按注意力/FFN 子层拆分），在划分复杂度与负载均衡之间进行权衡；
\emph{冻结感知的模型划分}，将块到阶段的分配形式化为整数规划问题，在满足显存约束与主流水级约束下最小化迭代时间，且目标函数显式依赖各阶段的冻结状态，从而随训练阶段动态调整划分策略；
\emph{提前终止调度器}，在 1F1B 等流水线调度基础上，识别从首端开始的连续冻结流水级并剪枝其反向计算与流水级间通信，在不影响模型收敛性的前提下提升吞吐。
在两种异构集群（Cluster-S、Cluster-L）与两种规模 MLLM（MLLM-3B、MLLM-12B）上的实验表明，MMoH 在 no-freeze、freeze-encoder、freeze-llm、freeze-both 四种场景下相对 Megatron-LM、Whale、Espresso 均可取得最高吞吐量，最高可达约 1.77$\times$ 加速，且提前终止调度器在冻结场景下可带来约 8\%--19\% 的额外增益，并具有良好的可移植性。

\textbf{（2）HR-MMoH：面向异构 GPU 集群的多模态大语言模型重计算技术。}

针对现有重计算策略在同构假设下采用全局统一配置、难以在异构集群上同时兼顾显存安全与计算效率的问题，本文在 MMoH 的划分与调度基础上，提出并实现了 HR-MMoH 的异构重计算方法。
HR-MMoH 使各流水级根据自身显存与算力条件采用差异化的重计算粒度（如 full/selective）与子模块选择，在降低 OOM 风险的同时减少多余重算、平衡流水级负载，与 MMoH 形成“划分—调度—重计算”多级优化。
第四章在更大批次与更长序列的实验设定下表明，HR-MMoH 在 no-freeze、freeze-encoder、freeze-llm、freeze-both 四种冻结场景中均取得最短迭代时间，相对 Espresso 的迭代时间缩短约 6.1\%--23.1\%，在 Whale 可训练的三种冻结场景中缩短约 11.0\%--40.6\%。
这说明按流水级差异化配置能够系统地优于全局统一策略，并验证了与 MMoH 协同优化的有效性。

综上，本文在异构 GPU 集群上 MLLMs 并行训练这一方向上，从\emph{划分与调度}与\emph{重计算优化}两条线给出了系统性的方法设计与实验支撑，为实际部署中的混合集群与分阶段冻结训练场景提供了可参考的技术路径。

\section{局限性及未来工作展望}

结合前文实验条件与工程实现，本节从集群规模、模型类型、异构硬件与框架集成四个方面归纳研究局限，并给出与之对应的后续研究方向。

\subsection{研究局限性}

\textbf{（1）集群规模有待扩展。}
本文在 Cluster-S（16 卡）与 Cluster-L（32 卡）两类小规模异构集群上完成了 MMoH 与 HR-MMoH 的验证，尚未在百卡及以上规模的生产级集群中检验规划器求解、剖析搜索与运行时调度的可扩展性与稳定性。

\textbf{（2）模型类型的覆盖仍不充分。}
现有工作主要面向典型的视觉—语言 MLLM 结构（编码器 + 投影层 + LLM 基座），实验模型规模为 3B 与 12B。
对 MoE 架构、文生图/文生视频等多模态生成模型，以及参数规模更大、模态更丰富的 Omni 类全模态模型，本文尚未系统评估上述方法在划分粒度、显存剖析与重计算配置搜索等方面是否仍适用。

\textbf{（3）异构集群类型的覆盖仍不充分。}
实验集群以 NVIDIA 消费级 GPU（RTX 3090、RTX 2080 Ti、RTX 2080）混合部署为主，软件栈亦基于 Megatron-LM 所依赖的 CUDA 生态。
对跨厂商异构场景——如华为昇腾、寒武纪等国产加速器，以及 AMD 等非 NVIDIA 加速器，还有数据中心级 GPU（如 H100）与消费级 GPU 的混合集群——尚未开展适配与性能验证。

\textbf{（4）工程集成与自动化程度有限。}
MMoH 与 HR-MMoH 的实现与 Megatron-LM 的训练流程、并行语义及配置接口深度耦合，重计算规划结果以 JSON 等形式在进程初始化阶段注入。
与 DeepSpeed、PyTorch FSDP 等其他主流训练框架的对接仍不充分，跨框架迁移与自动化部署成本较高。

\subsection{未来研究工作}

针对上述局限，后续研究可沿以下四个方向展开。

\textbf{（1）更大规模的集群验证。}
在百卡、千卡级异构集群上开展端到端实验，评估 MMoH 整数规划与 HR-MMoH 配置搜索在大规模流水并行下的求解时延、通信开销与负载均衡效果；结合公有云（如阿里云、华为云、腾讯云等）提供的弹性 GPU 资源，验证方法在接近工业部署规模时的鲁棒性与可运维性。

\textbf{（2）更丰富的多模态模型支持。}
将复合粒度模型抽象与冻结感知划分推广至 MoE、多模态生成及 Omni 全模态模型：在模型块列表中纳入专家路由、扩散解码等模块，扩展剖析表以覆盖新的显存与计算特征，并在更大参数规模与更长上下文设定下验证 HR-MMoH 的异构重计算收益。

\textbf{（3）更加异构的硬件场景。}
面向数据中心级 GPU、非 NVIDIA 加速器及国产 GPU 构建异构集群测试床，研究设备拓扑识别、算力—显存比建模与通信代价估计在不同软件栈下的可移植性；在跨厂商硬件上复现 MMoH 的划分—调度与 HR-MMoH 的重计算优化，形成面向国产算力生态的适配方案。

\textbf{（4）更易用的框架集成方式。}
在保持单卡数学语义不变的前提下，将 MMoH 规划器与 HR-MMoH 重计算配置器抽象为与具体训练后端解耦的模块，提供对 DeepSpeed、PyTorch FSDP 等框架的插件式或中间层集成路径；降低异构并行策略的配置与切换成本，便于在现有工业训练流水线中按需启用本文方法。

综上所述，本文在面向异构 GPU 集群的 MLLMs 并行训练方面取得了阶段性成果；后续宜从更大规模集群、更丰富模型形态、更广硬件覆盖以及更通用工程集成四个维度继续推进，为异构算力环境下多模态大模型训练提供可扩展、可落地的技术支撑。
